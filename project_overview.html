1. System Architecture

High-level components, data pipelines, and third-party integrations

Data Ingestion Layer

  • • Chrome History Copying: Reads local Chrome SQLite file safely into History_copy to avoid lock errors.
  • • URL Parsing & Cleaning: Extracts standard domain netlocs and Google Search queries (e.g. q=...).
  • • Chrome Timestamp Conversion: Translates microsecond epoch timestamps starting from 1601-01-01 into standard datetime objects.
  • • Relational DB Storage: Persists records into PostgreSQL/SQLite via SQLAlchemy ORM (BrowserHistory model).

AI Routing & RAG Layer

  • • Structured Router: Gemini 3.5 Flash Lite parses queries with Pydantic schemas into exact vs semantic search mode.
  • • ChromaDB Vector Store: Converts SQL history into LangChain Document objects stored in Brower_history collection.
  • • HuggingFace Embeddings: all-MiniLM-L6-v2 generates 384-dimensional dense vectors for semantic context.
  • • LangChain RAG Chain: Links similarity retriever, custom prompt, and Gemini LLM for conversational answers.

Analytics & Presentation Layer

  • • FastAPI Analytics Endpoints: Exposes 6 REST routes for overview metrics, top domains, category distribution, streak, hourly activity, & insights.
  • • React 18 Dashboard: Built with Vite, Tailwind CSS, Lucide icons, and Recharts for horizontal bar charts, donut charts, and heatmaps.
  • • Interactive Chat Interface: Tabbed navigation with live route badge indicators ("semantic" / "exact") and quick prompt triggers.
  • • Theme Persistence: Dark & light theme toggle synced to document HTML root class.

6. Technical Execution Strategy: How We Will Do It

Step-by-step implementation methodology for future developments

1

Step 1: Real-time Ingestion via Chrome Extension Webhooks

We will develop a Manifest v3 Chrome Extension with a background.js service worker monitoring chrome.history.onVisited and chrome.tabs.onUpdated events. The extension will send live JSON payloads to a newly created FastAPI endpoint POST /api/history/stream.

Payload: { "title": str, "url": str, "domain": str, "visit_time": ISOString, "dwell_seconds": int }
2

Step 2: Automated Vector Store Delta Syncing

Instead of running full batch synchronization with sync_vector.py, we will implement an asynchronous background worker using FastAPI's BackgroundTasks or Celery. Upon receiving a new history record, it will immediately embed and add the single vector into ChromaDB in real-time.

3

Step 3: Productivity & Email Digest Engine

We will add a background scheduler (APScheduler) running every Sunday at 8 PM. It will aggregate weekly visit counts, generate an AI summary of research topics via Gemini, build a responsive HTML email template, and dispatch it via SMTP or Resend/SendGrid API.

4

Step 4: Frontend Time-Series & Interactive Controls

We will update AnalyticsPage.jsx to pass a selected date range parameter (?start_date=...&end_date=...) to all backend endpoints, updating SQL aggregate functions accordingly to render responsive temporal comparisons.
